## 세 세션을 한 문장으로

> **무신사는 "무엇을 만들지 말지 결정하는 법"을, LG AI연구원은 "만든 것이 무엇으로 만들어졌는지 증명하는 법"을, SailPoint는 "만든 것이 무엇에 접근하는지 통제하는 법"을 말했다.**
> 셋 다 같은 전제 위에 서 있다 — **기록되지 않은 것은 판단할 수 없다.**

## 교차 정리 — 무신사 × LG AI연구원

| | 무신사 (길기용) | LG AI연구원 (조정원) |
|---|---|---|
| **관점** | 도입 판단 — 살까 / 만들까 / 안 할까 | 공급망 신뢰 — 무엇으로 만들어졌는지 증명 가능한가 |
| **핵심 주장** | "일관된 것은 결론이 아니라 **기준**입니다" | "신뢰는 언제나 **'보이는가'**의 문제였습니다" |
| **언제 기록하나** | 시작 전에 '멈출 기준'을 **계약서보다 먼저** | 학습 전에 데이터 계보를 **문장이 아닌 그래프로** |
| **적** | 하이프, 매몰비용, "다들 하니까" | 라벨, "오픈이니까 괜찮겠지", 재배포 체인 |
| **자동화한 것** | 판단이 아니라 **검증 절차**(가드레일 지표) | 판단이 아니라 **추적**(에이전트, 수작업 대비 45배) |
| **자동화하지 않은 것** | 환불·보상 판정, 분쟁 소지 확인 → 100% 사람 | **최종 법적 판단** → 100% 사람 |
| **핵심 수치** | AI 활용 가능 문의 영역 **10%**, 상담 인입 **30% 감소** | 「상업적 이용 가능」 라벨 **2,852개 → 실제 605개(21.2%)** |
| **경고** | "AI 성능이 아니라 **AI가 필요한 문제의 크기**를 재라" | "**결함은 최종 데이터셋이 아니라 아무도 안 보는 출발점**에 있다" |

### 두 세션이 만나는 지점

무신사가 외부 업체 계약에 건 3조건 중 **③ "어떤 LLM으로 바꾸더라도 돌아가는 구조"** 는 벤더 종속 방지책이지만, LG의 관점에서 읽으면 **모델 계보를 우리가 통제하겠다**는 선언이기도 하다.

반대로 LG가 말한 **"구매 부서는 이제 SBOM을 요구하듯 데이터 출처를 요구한다"** 는, 무신사식 TCO 계산서에 **새 비용 항목**이 하나 추가된다는 뜻이다 — 벤더의 학습데이터 계보를 검증하는 비용.

### SailPoint 세션이 앞의 두 세션에 더하는 것

무신사의 AI Chat Agent와 Visual AI는 **운영 단계에 들어간 에이전트**다. SailPoint 세션은 그 다음 질문을 던진다 — **그 에이전트들은 어떤 NHI로 무엇에 접근하고 있고, 오너는 누구이며, 사고가 나면 몇 시간 안에 끌 수 있는가.**

- 무신사의 "AI에게 맡기지 않은 영역"(환불·보상 판정, 분쟁 소지 확인)은 **정책 선언**이다. SailPoint의 주장은 그 선언을 **접근통제로 강제**해야 실효가 있다는 것 — JIT·ZSP·IBAC
- LG의 AI-BOM이 **학습 데이터의 계보**를 추적한다면, SailPoint의 Identity Graph는 **런타임 접근의 계보**(사람 → 에이전트 → NHI → 크리덴셜)를 추적한다. **같은 발상을 다른 축에 적용한 것**
- 셋을 합치면 하나의 문장이 된다: **무엇을 만들지 정하고(무신사), 무엇으로 만들었는지 기록하고(LG), 무엇에 접근하는지 통제한다(SailPoint).**

## 팀에서 바로 쓸 체크리스트 (세 세션 종합)

### A. AI 과제를 시작하기 전 (무신사)
- [ ] **가드레일 5종을 계약 전에 문서로 확정** — 에스컬레이션율 / 이탈률 / 구축비 / 건당 운영비 / 응답 지연 SLA(P50·P95·P99). 숫자를 구체적으로 (무신사: "5초 이내", "Pass율 80%")
- [ ] **비용은 도입가가 아니라 TCO** — 구축·인프라·데이터 관리·커스터마이징·품질관리/유지보수 + **토큰 비용**
- [ ] **매몰비용 규칙** — MVP 단계에서만 쓰는 기능은 구축비를 **1.5배**로 계산해 합산
- [ ] **"AI 성능"이 아니라 "AI가 필요한 문제의 크기"를 먼저 측정** (무신사: 문의를 60/30/10으로 분해 → 적용 가능 영역이 10%뿐임을 발견)
- [ ] **라이선스 구매 전 프로토타입 → 10% 사용자에게 배포**해 가설부터 깬다
- [ ] **중단을 곁가지가 아니라 같은 크기의 갈래로** 그린다

### B. 외부 업체·솔루션 계약서에 (무신사 + LG)
- [ ] ① **우리 클라우드에 직접 구축** ② **릴리즈 후 인수인계** ③ **LLM 교체 가능 구조**
- [ ] **OOTB 최대 활용, 커스터마이징은 내부 개발** (무신사: 3개월 릴리즈의 실제 원인)
- [ ] **학습데이터 출처·라이선스·취득 방법 고지 조항** — 표준 언어로 **SPDX 3.0 AI/Dataset Profile** 지목

### C. 모델·데이터셋을 들여올 때 (LG)
- [ ] **라벨을 그대로 믿지 않는다** — 허깅페이스 라이선스의 66%가 실제와 다른 카테고리, 그것도 **더 관대한 쪽으로** (Data Provenance Initiative)
- [ ] **인기 ≠ 안전** — Most Downloaded / Most Liked는 벤치마크 신호이지 법적 신호가 아니다
- [ ] **취득 방법을 로그로 남긴다** — Bartz가 증명한 것은 "학습했는가"가 아니라 **"어떻게 취득했는가가 배상액을 정한다"**
- [ ] **추적은 자동화, 판단은 사람**

### D. 규제 데드라인 (LG)
- [ ] **한국 AI 기본법** — 2026-01-22 시행 (규제 적용은 최소 1년 이상 유예, 계도 중심)
- [ ] **EU AI Act 제53조(1)(d)** — 학습 콘텐츠 요약 공개 의무 2025-08-02 발효, **집행 2026-08-02**, 기존 모델 2027-08-02까지. 위반 시 최대 **1,500만 유로 또는 매출 3%**. **오픈소스 모델도 대상**
- [ ] **캘리포니아 AB 2013** — **2026-01-01 시행**, 2022-01-01 이후 공개 시스템 대상, **12개 항목** 사전 게시, **영업비밀 예외 없음**

### E. 에이전트를 운영에 넣을 때 (SailPoint)
- [ ] **NHI를 1등급 아이덴티티로 승격** — 사람은 HR이 SoR이지만 NHI는 SoR이 없다. **디스커버리가 SoR을 대신**해야 한다
- [ ] **에이전트를 한 덩어리로 보지 않는다** — Embedded / Delegated / Autonomous / User-driven은 통제 모델이 다르다 (RBAC ↔ JIT ↔ IBAC)
- [ ] **가장 먼저 확인할 리스크 3종** — ① AI 클라이언트(Cursor·Claude CLI)가 특권 NHI 토큰을 쓰고 있는가 ② 퇴사자 PAT가 살아 있는가 ③ 협업 툴(Confluence·SharePoint·Drive)에 시크릿이 올라가 있는가
- [ ] **오프보딩에 토큰 회수를 넣는다** — PAT는 사람에게 묶여 있는데 퇴사 후에도 살아남는다
- [ ] **시크릿 로테이션은 자동화하지 않으면 일어나지 않는다**
- [ ] **킬스위치를 미리 정의** — 사고 시 비활성화 대상이 에이전트인지 크리덴셜인지, 롤백은 어떻게 하는지

## 이 정리에서 확실한 것과 아닌 것

**확실한 것** — 배포 PDF 덱에 인쇄된 내용, 외부 출처로 교차 검증된 판례·규제 일정

**주의할 것**
- 무신사의 성과 수치(2배, 40%, 89%, 94%, 30% 감소, 35% 채용)는 **전부 내부 산출이며 배포 덱에서는 빠졌다.** 산식·전제가 공개되지 않았으므로 타사에 그대로 이식하지 말 것
- LG의 2,852 → 605 역시 **자체 추적 결과**다. 다만 Data Provenance Initiative의 독립 감사가 **같은 방향**을 가리킨다
- "GEMA v. Suno 독일 연쇄 패소(2026)"는 이번 웹 검색으로 **확인하지 못했다** — 인용 시 단서 필요
- Thomson Reuters v. ROSS는 1심 원고 승이지만 **제3연방항소법원 항소 진행 중**(2026-07 구두변론) — "확정된 법리"로 인용하면 안 된다
