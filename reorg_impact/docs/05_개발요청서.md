## 지시사항

당신은 사내 IAM 시스템의 조직개편 영향 분석 도구를 구현한다.

### 절대 규칙

1. **정의되지 않은 동작을 임의로 구현하지 않는다.** `TODO: 정의 필요` 주석으로 표시하고 넘어간다.
2. **컬럼명을 추측하지 않는다.** 03 데이터딕셔너리에 실제 컬럼명이 없으면 상수로 분리하고 `TODO`로 표시한다.
3. **조직명(orgName)을 판정 로직에 사용하지 않는다.** 출력 표시용으로만 쓴다.
4. **모든 임계치를 하드코딩하지 않는다.** 설정 파일로 분리한다.
5. **조용한 실패를 만들지 않는다.** 스킵·경고는 사유와 함께 전부 로그에 남긴다.
6. **판정 결과에 근거 값을 함께 반환한다.** 왜 그렇게 판정했는지 알 수 없는 결과는 쓸모없다.

### 인코딩 — 전 구간 UTF-8

| 대상 | 규칙 |
|---|---|
| 소스코드 파일 | UTF-8 |
| 입력 CSV 읽기 | **UTF-8만 허용.** BOM은 제거하고 읽는다 |
| 출력 CSV 쓰기 | **UTF-8 with BOM** (Excel 한글 깨짐 방지) |
| 출력 md · 로그 | UTF-8 (BOM 없음) |
| 콘솔 출력 | UTF-8 |

입력이 UTF-8이 아니면 **자동 변환하지 말고 즉시 중단**한다. 조용히 변환하면 깨진 값을 정상으로 오인한다. 에러 메시지에는 감지된 인코딩과 **해결 방법**을 함께 적는다.

```
[입력 오류] orgs_before.csv 가 UTF-8이 아닙니다 (감지: CP949)
  → 메모장에서 열어 "다른 이름으로 저장 > 인코딩: UTF-8" 로
    다시 저장한 뒤 올려주세요.
```

Python 기준 참고:
- 읽기: `encoding="utf-8-sig"` (BOM 자동 제거)
- 쓰기(CSV): `encoding="utf-8-sig"`, `newline=""`
- 쓰기(md/로그): `encoding="utf-8"`
- 인코딩 검증: 파일을 `utf-8`로 디코딩 시도해 실패하면 중단

### 데이터 구조

```
Org      { orgCode, orgName, parentCode }
Member   { userId, orgCode, jobCode }
Assign   { userId, effectiveDate, reasonCode, beforeOrgCode, afterOrgCode }
Rule     { ruleId, permissionId, ruleType, deptConditions[], jobCodes[] }
           deptConditions[] = [ { orgCode, includeSubDept } ]
           ruleType = AUTO | BLOCK
           jobCodes 가 비어 있으면 직무 조건 미검사
```

> rules.csv는 **1룰-1부서조건 1행**으로 들어올 수 있다. ruleId 기준으로 그룹핑해 하나의 Rule 객체로 재구성한다. 실제 추출 형태는 03 문서 5장 참조.

### 부서 매칭 규칙 (기존 운영 로직, 변경 금지)

```
includeSubDept = false  →  user.orgCode == rule.orgCode 인 경우만
includeSubDept = true   →  rule.orgCode 이거나, 트리상 하위
                           어느 depth든 매칭 (깊이 제한 없음)

한 룰 내 부서조건끼리   →  OR
부서조건 ↔ 직무조건     →  AND
jobCodes 비어 있음      →  직무 조건 검사 생략
```

## 개발 순서 — 한 번에 하나씩 요청할 것

전체를 한 번에 만들지 않는다. 아래 순서로 분할해 요청하고, 각 단계가 동작하는 것을 확인한 뒤 다음으로 넘어간다.

### 1단계. 입력 로더 + 검증
- CSV 6종 로드
- **인코딩 검증** (UTF-8 아니면 중단, 위 메시지 형식)
- 필수 컬럼 존재 확인
- 조직코드 중복 검사
- 컬럼명은 전부 상수로 분리 (실제 값 확정 전까지 `TODO`)

**검증 결과 처리**

| 상황 | 처리 |
|---|---|
| 인코딩 불일치 | 중단 |
| 필수 컬럼 누락 | 중단 |
| 조직코드 중복 | 중단 |
| parentCode 미존재 | 경고 + 고립 처리 |
| 임직원 조직코드 미존재 | 경고 + 집계 제외 |
| 룰 부서조건 비어 있음 | 경고 + 해당 룰 스킵 |

### 2단계. 조직 트리 빌더
- before / after 각각 트리 구성
- 특정 조직의 전체 하위 조직을 말단까지 반환하는 함수
- **순환참조 방어**: 해당 경로만 스킵 + 경고 로그. 전체 중단 금지
- 깊이 제한 없음

### 3단계. 발령 필터
- 발령사유코드가 조직개편인 건만 추출
- 전배 전량 제외
- 개편 기준일 ±N일 범위만 인정
- 동일 사번 복수 발령 시 최신 건
- 산출물: 조직코드 간 인원 이동 매트릭스 `{ from: { to: count } }`

### 4단계. SC 분류기
- 02 문서 5장 판정 순서를 그대로 구현
- 각 조직코드에 SC 코드 + CF 코드 부여
- **evidence 값 동반 반환**: 인원 이동 비율, parentCode 일치 여부, 하위조직 구성 일치 여부
- 짝짓기 제약 준수 (1:1, 중복 배정 금지)
- 인원 0명 조직은 CF-L 초과 불가

### 5단계. 고아 룰 검출기
- 전체 룰 스캔, 조직코드가 개편 후 목록에 없는 룰 추출
- **다른 단계와 무관하게 단독으로 동작해야 한다**
- 이것이 최종 안전망이다. 분류 로직이 무엇을 놓치든 여기에 걸린다

### 6단계. 룰 영향도 분석
- 범위확대 검출 (SC-01, SC-08)
- 충돌 룰 검출 — 동일 권한에 AUTO/BLOCK 혼재
- 중복 룰 검출 — 동일 권한 + 동일 종류 + 동일 직무

### 7단계. 시뮬레이션 엔진
- 기존 판정 로직 재현
- 룰별 before / after 대상자 명단 산출
- 차집합으로 신규·이탈 인원 계산

### 8단계. 리포트 생성
- org_changes.csv / rule_actions.csv / member_impact.csv / summary.md
- CSV는 UTF-8 with BOM
- summary.md 최상단에 **고아 룰 건수**를 먼저 표시

### 9단계. 테스트 데이터 생성
- SC-00 ~ SC-09 각 케이스별 샘플 CSV 세트
- 전배가 섞인 케이스 포함 (필터링이 동작하는지 검증용)
- 순환참조 케이스, 인원 0명 조직 케이스 포함
- **전부 UTF-8로 생성**

## 출력 파일 명세

### org_changes.csv
`orgCode_before`, `orgCode_after`, `orgName_before`, `orgName_after`, `parentCode_before`, `parentCode_after`, `scenarioCode`, `confidenceCode`, `evidence_member_ratio`, `evidence_parent_match`, `evidence_child_match`, `affected_rule_count`

### rule_actions.csv
`ruleId`, `permissionId`, `ruleType`, `orgCode_current`, `orgCode_proposed`, `scenarioCode`, `confidenceCode`, `actionType`, `requiresApproval`, `reason`

`actionType`: `NONE` / `REPLACE_CODE` / `REVIEW_TRANSFER` / `REVIEW_DELETE` / `REVIEW_DUPLICATE` / `MANUAL`

### member_impact.csv
`ruleId`, `permissionId`, `ruleType`, `added_count`, `removed_count`, `added_userIds`, `removed_userIds`

### summary.md
사람이 읽는 요약. 형식 예시:

```
■ 고아 룰                          2건   ← 최우선 확인
■ 자동 반영 가능                    5건
■ 승인 필요                        12건
■ 수동 검토 필수                    8건

[SC-07] B001 → A001 흡수  |  CF-H  |  인원 34명
  ■ 고아 예정 룰 (B001)          3건
    - R-112  X권한 AUTO   → [이관/폐기/보류]
    - R-118  Y권한 BLOCK  → [이관/폐기/보류]
  ■ A001 기존 룰 범위확대 경고    2건
    - R-051  X권한 AUTO   → 신규 부여 예정 34명
  ■ 충돌 감지                     1건
    - X권한: A001 R-051(AUTO) ↔ B001 R-112(AUTO) 중복
```

## 코드 작성 규칙

- 함수 단위로 작성하고, 각 함수 위에 한 줄 주석
- 판정 로직과 입출력 로직을 분리한다
- 설정값은 별도 파일 (`config.yaml` 또는 `config.py`)
- 로그는 파일과 콘솔 양쪽에 남긴다
- 같은 입력이면 항상 같은 결과가 나와야 한다 (결정론적)
- 개별 건 실패 시 해당 건만 SC-09로 처리하고 전체는 계속 진행
