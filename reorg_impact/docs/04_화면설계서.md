# 04. 화면 설계서

> 검토자가 파일을 올리고, 영향도를 보고, 조치를 결정하는 화면.
> 동작하는 프로토타입 HTML이 함께 제공된다. 이 문서는 그 설계 의도를 설명한다.

---

## 1. 사용자와 목적

**사용자**: 조직개편 때 권한 룰을 점검해야 하는 보안 담당자
**목적**: 놓치면 안 되는 것을 먼저 보여주고, 손대야 할 것만 골라서 결정하게 한다

이 화면의 성패는 **"내가 할 일이 몇 건인지"를 3초 안에 알 수 있는가**에 달려 있다.

---

## 2. 전체 구조 — 4단계

```
① 파일 올리기      ② 분석            ③ 영향도 검토        ④ 내보내기
   CSV 6종 준비       조직 변경 판정      룰 확인·조치 결정     결과 파일 받기
```

상단에 진행 순서를 **항상 고정 표시**한다. 각 단계에 번호, 이름, 한 줄 설명이 붙는다.

| 상태 | 표시 |
|---|---|
| 완료 | 번호 자리에 체크 표시, 눌러서 되돌아갈 수 있음 |
| 현재 | 강조색, 하단 밑줄 |
| 미도달 | 흐림 처리, 클릭 불가 |

검토와 결정을 한 화면(3단계)에 합쳤다. 보면서 정하는 일이라 나눌 이유가 없다.

---

## 3. 각 화면

### 3-1. 파일 올리기

2열 그리드로 6개 슬롯을 배치한다. 슬롯마다 파일 용도를 한글로 표시하고, 올라가면 초록 테두리와 체크 표시로 바뀐다.

- 하단에 `n / 6개 올림` 카운터
- 6개 전부 올라가야 `분석 시작` 버튼 활성화
- 헤더에 `CSV · UTF-8` 표기

**인코딩 오류 처리**

UTF-8이 아닌 파일은 해당 슬롯을 빨간색으로 표시하고, 고치는 방법까지 알려준다.

```
orgs_before.csv 가 UTF-8이 아닙니다 (감지: CP949)
메모장에서 열어 "다른 이름으로 저장 > 인코딩: UTF-8"로
다시 저장한 뒤 올려주세요.
```

오류 메시지는 무엇이 잘못됐는지와 **어떻게 고치는지**를 함께 적는다. "파일 형식 오류" 같은 표현은 쓰지 않는다.

### 3-2. 분석

진행 단계를 텍스트로 보여준다.

```
파일을 읽는 중 → 조직 트리를 세우는 중 → 전배 발령을 걸러내는 중
→ 조직 변경을 분류하는 중 → 룰 영향도를 계산하는 중
```

"원본 데이터는 변경하지 않습니다"를 헤더에 명시한다. 권한을 다루는 도구라 검토자가 이걸 알아야 마음 놓고 누른다.

### 3-3. 영향도 검토 — 핵심 화면

**a) 최상단: 고아 룰 배너**

가장 먼저, 가장 크게 보여준다. 다른 걸 다 놓쳐도 이건 봐야 한다.

```
┌──────────────────────────────────────────────┐
│  2   지금 고장난 룰이 있습니다                 │
│      개편 후 사라진 조직코드를 가리키는 룰입니다.│
│      아무도 대상에 걸리지 않아 자동 부여도      │
│      신청 차단도 동작하지 않습니다.            │
└──────────────────────────────────────────────┘
```

0건이면 초록으로 바뀌고 "고장난 룰 없음"을 표시한다.

**b) 세 칸 요약**

| 칸 | 의미 |
|---|---|
| 그대로 반영해도 되는 건 | SC-02 / CF-H 등 자동 처리 가능 |
| 룰 수정 없이 대상자만 바뀌는 건 | SC-01, SC-08 — 확인만 필요 |
| 직접 결정해야 하는 건 | SC-04~07, SC-09 |

검토자는 **세 번째 칸 숫자만큼만** 손대면 된다.

**c) 변경 건 목록 (접었다 펴기)**

한 줄 요약:
```
[SC-07] [CF-H]  B001 → A001 흡수   정보보안기획팀 → 정보보안운영팀
                                    34명 · 룰 5건        ▾
```

펼치면 세 블록이 나온다.

```
■ 대상 조직이 사라진 룰  3건
  룰      권한    종류       직무    어떻게 할까요
  R-112   X권한   자동 부여  전체    [이관][폐기][보류]
  R-118   Y권한   신청 차단  전체    [이관][폐기][보류]

■ 대상자가 바뀌는 기존 룰  2건
  룰      권한    종류       새로 걸리는 인원  빠지는 인원
  R-051   X권한   자동 부여  +34명             —
  R-077   W권한   신청 차단  +34명             —

■ 확인이 필요한 충돌
  X권한이 A001 R-051(AUTO)과 B001 R-112(AUTO)에 중복으로
  걸려 있습니다. 이관하면 R-112는 불필요해집니다.
```

**d) 시나리오별 표시 차이 — 중요**

| 시나리오 | 표시 |
|---|---|
| SC-01 (조직이동) | **결정 버튼 없음.** 인원 증감만 표시하고 확인만 받는다 |
| SC-02 / CF-H | 결정 버튼 없이 "코드 치환" 안내만 |
| SC-04~07, SC-09 | 룰별 이관/폐기/보류 선택 |

SC-01에 이관/폐기 선택지를 주면 오히려 혼란스러워진다. 룰을 고치는 게 아니라 대상자가 바뀌는 것뿐이기 때문이다.

**e) 하단**

`결정 n / m건` 카운터. 필요한 결정을 다 해야 다음 단계로 넘어간다.

### 3-4. 내보내기

받을 파일 목록과 각 파일에 뭐가 들었는지 표시한다.

"이 도구는 룰을 직접 수정하지 않습니다"를 명시한다.

---

## 4. 용어 원칙

화면에서는 시스템 용어를 풀어 쓴다.

| 내부 용어 | 화면 표기 |
|---|---|
| AUTO | 자동 부여 |
| BLOCK | 신청 차단 |
| orphan rule | 대상 조직이 사라진 룰 |
| expanded | 대상자가 바뀌는 기존 룰 |

단, **SC / CF 코드는 그대로 노출**한다. 검토자와 개발자가 같은 말로 소통해야 하고, 리포트 파일에도 같은 코드가 찍히기 때문이다.

---

## 5. 구현 시 지킬 것

- 접근성: 키보드 포커스가 눈에 보일 것, `prefers-reduced-motion` 존중
- 반응형: 좁은 화면에서 진행바는 번호와 이름만 남기고 설명은 감춘다
- 브라우저 저장소(localStorage 등) 사용 금지 — 메모리 상태로만 관리
- 애니메이션은 사용자 동작에 대한 반응(펼침, 확인)에만 사용

---

## 6. 미정 사항

- [ ] 로그인·권한 체계 — 누가 이 화면에 접근할 수 있는지
- [ ] 검토 이력 저장 여부 — 누가 언제 무엇을 결정했는지 남길 것인지
- [ ] 승인자 분리 — 검토자와 승인자가 다른 사람인지
- [ ] 여러 명이 나눠서 검토하는 경우 지원 여부
