각 문서는 **단독으로 다른 AI 도구에 업로드해도 이해 가능하도록** 작성되었다.

**한 번에 한 가지 일만 시킬 것.**

## 인코딩 원칙 — 전 구간 UTF-8

이 프로젝트의 모든 입출력은 **UTF-8로 통일한다.**

| 대상 | 규칙 |
|---|---|
| 입력 CSV | UTF-8 (BOM 유무 무관, BOM은 읽을 때 제거) |
| 출력 CSV | UTF-8 with BOM ※ |
| 출력 md / 로그 | UTF-8 (BOM 없음) |
| 소스코드 파일 | UTF-8 |

※ 출력 CSV에만 BOM을 붙이는 이유: Excel이 BOM 없는 UTF-8 CSV를 CP949로 오인해 한글이 깨진다. 검토자가 Excel로 열 파일이므로 BOM을 붙인다.

**입력이 UTF-8이 아닐 때의 동작**
- 자동 변환하지 않는다. 조용히 변환하면 깨진 값을 정상으로 오인한다.
- 즉시 중단하고 아래 형태로 안내한다.

```
[입력 오류] orgs_before.csv 가 UTF-8이 아닙니다 (감지: CP949)
  → 메모장에서 열어 "다른 이름으로 저장 > 인코딩: UTF-8" 로 다시 저장한 뒤 올려주세요.
```

## 남은 액션 아이템

### A. 데이터 딕셔너리 작성 — **최우선**
현재 문서의 필드명은 전부 가칭이다. 실제 컬럼명을 모르면 코드가 반드시 틀린다.

필요한 것:
- [ ] CSV 6종의 **헤더 행** (첫 줄 그대로)
- [ ] 각 파일 **샘플 2~3행** (사번·이름은 가명 처리 가능, 형식만 유지)
- [ ] **발령사유코드 전체 목록**과 의미 — 조직개편/전배 구분값이 뭔지
- [ ] 조직코드 자릿수 규칙 (고정 길이인지, 앞자리에 의미가 있는지)
- [ ] 직무코드 예시 몇 개

→ 확보되면 `03_데이터딕셔너리.md` 를 채우고, 01·05 문서의 필드명을 실제 값으로 교체한다.

### B. 룰 목록 추출 방법 확인
- [ ] IAM 포털에서 권한 룰 전체를 CSV로 내려받을 수 있는지
- [ ] 불가하면 DB 직접 조회 또는 운영팀 추출 요청 경로 확보
- [ ] 한 룰에 부서 조건이 여러 개일 때 어떤 형태로 나오는지 (행 분리 / 한 셀에 나열)

### C. 개편 후 임직원 목록 확보 시점
- [ ] 개편 **발효 전**에 미리 돌려볼 것인지 확인
- [ ] 그렇다면 실제 명단이 없으므로, 발령 예정 데이터로 가상 명단을 만드는 로직이 추가로 필요

### D. 반영 경로 확정
- [ ] 승인된 변경안을 IAM 포털에 어떻게 넣을지 (수동 입력 / 일괄 업로드 / API)
- [ ] 일괄 업로드가 가능하면 그 포맷에 맞춰 출력 CSV를 설계

### E. 개발 환경
- [ ] 개발 언어 (Python 권장 — CSV 처리와 로컬 실행에 적합)
- [ ] 실행 방식 (CLI / 웹 화면 / 둘 다)

## 진행 순서 제안

```
1. A 확보  →  03 데이터딕셔너리 완성
2. B 확인  →  rules.csv 확보 가능 여부에 따라 범위 조정
3. 05 문서로 코드 구현 요청 (단계별 분할)
4. 04 문서로 화면 구현
5. C · D 는 1차 동작 확인 후 착수
```

A가 막히면 전체가 막힌다. 다른 건 나중에 해도 된다.
