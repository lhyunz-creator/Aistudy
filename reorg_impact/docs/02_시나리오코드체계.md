# 02. 시나리오 코드 체계

> 조직 변경을 분류하는 규칙. 이 문서의 코드값은 리포트·로그·테스트케이스에서 **공용 언어**로 사용한다.

---

## 1. 판정 원칙

- 모든 판정은 **조직코드(orgCode)와 상위조직코드(parentCode)만** 사용한다
- **조직명(orgName)은 판정에 일절 사용하지 않는다.** 리포트 출력 시 참고 정보로만 표시
- 인원 이동 추적은 **조직개편 발령 건만** 사용한다 (전배 제외)
- 하나의 조직코드에는 **하나의 SC 코드만** 부여한다
- 모든 임계치는 하드코딩 금지, 설정값으로 분리한다

---

## 2. SC 코드 — 조직 변경 유형

| 코드 | 명칭 | 판정 조건 | 룰 조치 | 자동반영 |
|---|---|---|---|---|
| SC-00 | UNCHANGED | 코드 존속, parentCode 동일 | 없음 | ○ |
| SC-01 | MOVED | 코드 존속, parentCode 변경 | **룰 수정 없음**, 시뮬레이션만 | ○ |
| SC-02 | RECODED | 소멸 1 → 신설 1 (단독 유입) | 조직코드 치환 | CF-H만 |
| SC-03 | CREATED | 신설, 대응 소멸코드 없음 | 없음 (신규 룰은 별도 수립) | ○ |
| SC-04 | ABOLISHED | 소멸, 유입처 없이 인원 분산 | 룰 삭제 또는 비활성 | ✕ |
| SC-05 | SPLIT | 소멸 1 → 2개 이상으로 분산 | 룰 복제 여부 결정 | ✕ |
| SC-06 | MERGED_NEW | 소멸 2개 이상 → 신설 1개로 수렴 | 룰 이관 여부 결정 | ✕ |
| SC-07 | MERGED_INTO | 소멸 1개 이상 → 기존 존속 코드로 수렴 | 룰 이관 여부 결정 | ✕ |
| SC-08 | EXPANDED | 존속 코드에 타 조직 인원 유입 | **기존 룰 범위확대 경고** | ✕ |
| SC-09 | UNDETERMINED | 근거 부족 또는 인원 0명 | 전건 수동 검토 | ✕ |

---

## 3. CF 코드 — 확신도

| 코드 | 조건 | 처리 |
|---|---|---|
| CF-H | 인원 이동 + 보조근거(parentCode 일치 또는 하위조직 구성 일치) 충족 | 자동 반영 가능 |
| CF-M | 인원 이동만 충족 | 승인 후 반영 |
| CF-L | 근거 부족 / 인원 0명 | 수동 입력 필수 |

한 건은 `SC-02 / CF-H` 형태로 표기된다. SC-02라도 CF-M이면 자동 치환하지 않고 승인 대기로 보낸다.

---

## 4. OR 코드 — 고아 룰

SC와 별개 축이다. 분류 결과와 무관하게 **항상 별도로 검사**한다.

| 코드 | 의미 |
|---|---|
| OR-01 | 룰의 조직코드가 개편 후 조직 목록에 없음 |
| OR-02 | 짝짓기 실패로 조치 없이 방치된 룰 |

---

## 5. 판정 순서

위에서부터 평가하고, **먼저 걸리는 것으로 확정**한다.

### 5-1. 존속 코드 (before / after 양쪽에 존재)

```
1. 타 소멸코드로부터 인원 유입 있음  →  SC-08
   (이때 유입원 소멸코드는 SC-07 로 별도 기록)
2. parentCode 변경                   →  SC-01
3. 그 외                             →  SC-00
```

### 5-2. 신설 코드 (after 에만 존재)

```
1. 유입된 소멸코드가 2개 이상        →  SC-06
   ※ 비율 무관. 통합 판정을 코드변경보다 우선한다
2. 유입된 소멸코드가 1개
   · 이동비율 >= MEMBER_THRESHOLD    →  SC-02
   · 미만                            →  SC-09
3. 유입 없음                         →  SC-03
```

### 5-3. 소멸 코드 (before 에만 존재)

```
1. 인원 0명                          →  SC-09
2. 인원이 단일 코드로 수렴 (>= MEMBER_THRESHOLD)
   · 대상이 신설코드                 →  SC-02 (짝)
   · 대상이 존속코드                 →  SC-07
3. 인원이 2개 이상으로 유의미하게 분산
   (각 분기 >= SPLIT_MIN_RATIO)      →  SC-05
4. 유입처 식별 불가 / 흩어짐          →  SC-04
```

---

## 6. 짝짓기 제약

- 한 소멸코드는 **최대 하나의 신설코드**와만 SC-02 짝을 이룬다
- 이미 짝지어진 신설코드는 다른 후보에서 제외한다
- 인원 0명 조직은 인원 근거를 계산할 수 없으므로 **CF-L 초과 불가, 자동 확정 금지**

## 7. 자동 반영 제약

- **SC-04 ~ SC-09 는 확신도와 무관하게 자동 반영 금지**
- SC-02 는 **CF-H 인 경우에만** 자동 치환 제안. CF-M / CF-L 은 승인 대기
- **SC-01 은 룰 수정 대상이 아니다.** 시뮬레이션 대상으로만 표시한다

---

## 8. 각 시나리오 해설

### SC-01 조직이동 — 가장 놓치기 쉬움
조직코드는 그대로인데 상위조직만 바뀐 경우다. 룰 테이블은 한 글자도 안 바뀌어서 정상으로 보인다. 그러나 `하위부서 포함` 룰의 대상자 명단이 조용히 달라진다.

```
b1 의 상위가 B팀 → C팀 으로 변경되면

  [B팀 + 하위포함] 룰  →  b1 인원 전원 이탈
  [C팀 + 하위포함] 룰  →  b1 인원 전원 편입
  [b1 직접지정] 룰     →  변화 없음
```

**룰을 고치는 게 아니라 인원 변동을 보여주는 것**이 이 케이스의 산출물이다.

### SC-02 코드변경 — 방치하면 룰이 죽는다
조직 실체는 같은데 코드만 바뀐 경우다. 코드가 키이므로 1차 분류에서는 `소멸 + 신설` 한 쌍으로 잘못 잡힌다. 후처리로 짝을 찾지 못하면 해당 룰은 죽은 코드를 가리킨 채 방치된다.

짝짓기 근거 세 가지:
| 근거 | 내용 | 강도 |
|---|---|---|
| 인원 이동 | 소멸코드 인원이 신설코드로 이동한 비율 | 가장 강함 |
| 상위조직 일치 | parentCode 동일 | 보조 |
| 하위조직 구성 | 하위 조직들도 함께 따라갔는지 | 보조 |

### SC-06 / SC-07 통합 — 두 갈래로 나뉜다

```
A + B → C (신규코드)   →  SC-06
  A도 B도 소멸. 양쪽 룰이 모두 고아가 된다.

A + B → A (기존코드 존속)  →  B는 SC-07, A는 SC-08
  B 룰만 고아가 되지만,
  A 룰은 멀쩡해 보이면서 대상자만 대폭 늘어난다.
```

**두 번째가 더 위험하다.** A는 1차 분류에서 SC-00으로 나오기 때문에 아무 신호가 안 뜬다. 그래서 SC-08을 독립 코드로 두어 반드시 한 줄 잡히게 한다.

### 통합 시 필수 산출물
1. 소멸조직 룰별 **이관 / 폐기 / 보류** 선택지 제시
2. 존속조직 기존 룰의 **범위확대 인원 수** 산출
3. **충돌 룰 검출** — 동일 권한에 AUTO와 BLOCK이 함께 딸려오는 쌍
4. **중복 룰 검출** — 동일 권한 + 동일 종류 + 동일 직무 조합

### SC-09 판정불가 — 인원 0명 조직에 주의
신설 대기 부서나 껍데기 조직은 인원 추적이 불가능하다. 그런데 **이런 조직에도 룰이 걸려 있을 수 있다.** 반드시 수동 검토로 보낸다.

---

## 9. 설정값

| 키 | 기본값 | 설명 |
|---|---|---|
| MEMBER_THRESHOLD | 0.9 | 단일 코드 수렴 판정 임계치 |
| SPLIT_MIN_RATIO | 0.1 | 분할 판정 시 유효 분기로 인정할 최소 비율 |
| REORG_DATE | (필수 입력) | 개편 기준일자 |
| REORG_DATE_TOLERANCE | 3 | 개편 발령 인정 일자 범위(±일) |
| REASON_CODE_REORG | (필수 입력) | 조직개편 발령사유코드 |
| REASON_CODE_TRANSFER | (필수 입력) | 전배 발령사유코드 |

임계치 근처 구간(예: 0.6 ~ 0.9)은 자동 확정하지 말고 **전부 사람 검토로 보내는 것이 안전하다.**
