# 03. 데이터 딕셔너리

> **상태: 미완성.** 아래 필드명은 전부 **가칭**이다.
> 실제 CSV 헤더를 확보해 이 문서를 채운 뒤에 개발을 시작해야 한다.
> 이 문서가 비어 있으면 코드형 LLM은 컬럼명을 **추측해서 만들고, 반드시 틀린다.**

---

## 0. 채우는 방법

각 파일에 대해 아래 세 가지를 확보한다.

1. **헤더 행** — CSV 첫 줄을 그대로 복사
2. **샘플 2~3행** — 사번·이름은 가명 처리 가능. **값의 형식만 유지되면 가짜 값이어도 무방**
3. **코드값 목록** — 발령사유코드처럼 정해진 값 집합이 있는 경우

그다음 아래 표의 `실제 컬럼명` 칸을 채우고, `형식`과 `허용값`을 샘플에 맞춰 수정한다.

---

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 인코딩 | **UTF-8 고정.** BOM 유무는 무관하며 읽을 때 제거한다 |
| 구분자 | 쉼표(`,`) |
| 헤더 | 첫 줄에 반드시 존재 |
| 빈 값 | 빈 문자열로 표기. `NULL`, `-`, `없음` 등 문자열 사용 금지 |
| 공백 | 앞뒤 공백은 읽을 때 제거(trim) |
| 날짜 | `YYYY-MM-DD` 또는 `YYYYMMDD` 둘 다 허용 |
| 불리언 | `TODO: 실제 표기 확인` — Y/N, true/false, 1/0 중 무엇인지 |

**UTF-8이 아닌 파일은 자동 변환하지 않고 즉시 중단한다.** 조용히 변환하면 깨진 값을 정상으로 오인하게 된다.

## 5. rules.csv — 권한 룰 목록

| 가칭 | 실제 컬럼명 | 필수 | 형식 | 설명 |
|---|---|---|---|---|
| ruleId | `TODO` | Y | 문자 | 룰 ID |
| permissionId | `TODO` | Y | 문자 | 권한 ID |
| ruleType | `TODO` | Y | 코드 | 자동화룰 / 통제룰 구분 |
| orgCode | `TODO` | Y | 문자 | 부서 조건 조직코드 |
| includeSubDept | `TODO` | Y | 불리언 | 하위부서 포함 여부 |
| jobCodes | `TODO` | N | 문자 | 직무코드. 복수면 구분자 필요 |

### 부서 조건이 여러 개일 때 — 형태 확인 필수

한 룰에 부서 조건이 여러 개(OR) 들어갈 수 있다. 추출 형태가 둘 중 무엇인지 확인한다.

**형태 A — 행 분리 (권장)**
```
ruleId, permissionId, ruleType, orgCode, includeSubDept, jobCodes
R-112,  X권한,        AUTO,     B001,    Y,              
R-112,  X권한,        AUTO,     B002,    N,              
```
→ ruleId 기준으로 그룹핑해 하나의 룰로 재구성한다.

**형태 B — 한 셀에 나열**
```
ruleId, permissionId, ruleType, orgCodes,        includeSubDept, jobCodes
R-112,  X권한,        AUTO,     B001;B002,       Y;N,            
```
→ 구분자로 분리하되, 조직코드와 하위포함 플래그의 **순서가 일치하는지** 반드시 확인한다. 어긋나면 전혀 다른 룰이 된다.

**확인 필요**
- [ ] IAM 포털에서 룰 전체를 CSV로 내려받을 수 있는가
- [ ] 위 형태 A / B 중 어느 쪽인가
- [ ] ruleType 실제 코드값 (AUTO/BLOCK? 1/2? 자동/통제?)
- [ ] 비활성 상태 룰이 포함되는가 (포함되면 상태 컬럼 필요)
- [ ] 직무 조건 외에 다른 조건(직급, 재직상태 등)이 있는가

## 6. 출력 파일 인코딩

| 파일 | 인코딩 |
|---|---|
| org_changes.csv | UTF-8 **with BOM** |
| rule_actions.csv | UTF-8 **with BOM** |
| member_impact.csv | UTF-8 **with BOM** |
| summary.md | UTF-8 (BOM 없음) |
| 로그 파일 | UTF-8 (BOM 없음) |

출력 CSV에만 BOM을 붙이는 이유는 Excel 때문이다. Excel은 BOM 없는 UTF-8 CSV를 CP949로 오인해 한글을 깨뜨린다. 검토자가 Excel로 열 파일이므로 BOM을 붙인다. md와 로그는 붙이지 않는다.

---

## 7. 입력 검증 규칙

로드 직후 수행한다.

**중단 (에러 종료)**
- 인코딩이 UTF-8이 아님
- 필수 컬럼 누락
- 조직코드 중복

**경고 후 계속**
- parentCode가 조직 목록에 없음 → 해당 조직 고립 처리
- 임직원의 조직코드가 조직 목록에 없음 → 집계에서 제외
- 조직 트리 순환참조 → 해당 경로만 스킵. **전체 중단 금지**
- 룰의 부서 조건이 비어 있음 → 잘못된 룰로 스킵

모든 경고는 사유와 함께 로그에 남긴다. 조용히 넘기지 않는다.
